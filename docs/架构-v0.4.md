# Carapace v0.4 架构

## 边界

```text
SwiftUI 面板 / 编辑窗口 ─┐
                         ├─ AppState（主线程状态与行情调度）─ Store（唯一写入口）
MCP stdio 进程 ──────────┘                                   └─ SQLite
                              QuoteService（主备行情）
```

- `CarapaceCore` 不依赖 UI：模型、SQLite、行情、MCP、提醒计算可独立测试。
- `Carapace` 只负责 AppKit/SwiftUI、窗口、菜单栏、系统通知。
- 所有写操作在 `BEGIN IMMEDIATE` 事务中先写 `changes`，再更新 `positions` / `plans`。
- MCP 与 UI 使用同一 Store，并通过 Darwin 通知让已打开的面板重载。

## 数据

| 表 | 角色 |
|---|---|
| `changes` | 只追加事实流水，记录前后数量/成本、费用、档位 ID 和计划版本 |
| `positions` | 当前持仓投影，可由流水最新状态重建 |
| `plans` | 当前计划投影，每个持仓唯一 |
| `alerts` | 提醒生命周期：首次触发、最近触发、确认、恢复 |
| `meta` | 初始化标记等少量元数据 |

v3 起计划档位有稳定 `id`。成交通过 `level_id` 和 `plan_version` 关联计划；`level_price` 只用于读取旧流水。数据库升级到 v3 前生成一次性 `.v2-backup`。

## 状态规则

- 计划执行状态：`type in (buy, sell, clear)` 且 `level_id` 非空；旧流水只有在方向和价格唯一匹配当前档位时才迁移。
- 成交匹配：档位必须存在、方向一致、属于当前计划、尚未执行。反向和重复执行都会拒绝。
- 估值：没有有效报价，单只持仓的价值、盈亏、下一档均为 `nil`；汇总不完整时也不显示合计盈亏。
- 行情：每只持仓按 `source` 选择主源，单只主源失败/缺失时使用另一来源。报价缓存带来源和行情时间。
- 提醒：启动、持仓重载和行情检查后，根据活动条件同步提醒；条件消失时归档，不删除。确认时间持久化。

## 已知边界

- `MarketHours` 只按星期与固定时段判断，没有交易所节假日表。
- 金额使用 Double，适合个人记录，不是会计系统。
- MCP 服务与 App 共享同一 SQLite 文件，不提供网络端口或鉴权。
- ad-hoc 签名，无公证、无自动更新。
