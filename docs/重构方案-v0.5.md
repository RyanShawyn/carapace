# Carapace v0.5 重构方案

> 状态：草案，随 UI 原型迭代
> 分支：`refactor/ai-app`
> 原型：[design/v0.5/app.html](../design/v0.5/app.html)
> UI 规范：[UI设计规范-v0.5](UI设计规范-v0.5.md)
> 日期：2026-11-05

## 0. 结论

把 Carapace 从「菜单栏持仓看板 + MCP 工具」改成本机优先的**持仓决策与复盘系统**：菜单栏继续快速查看，主应用负责建仓、计划、成交、复盘、记忆和通知，AI 作为内置 Agent 直连 magpie 或常见协议供应商。

这一版在上一稿基础上做了六处结构性调整：

| 反馈 | 方案变化 |
|---|---|
| magpie 里有很多模型，没有展示出来；要支持常用协议和示例 | 新增完整模型目录、供应商管理、5 种协议接入、任务路由和接入示例 |
| 数据最终是为了盈利，要归纳总结和通知 | 总览改为「需要你处理 + 本周结果」；复盘增加结果归因；通知增加仓位/回撤 |
| 不同产品类型分析方式不同，复盘和计划都依赖它 | 新增「分析框架」：个股/黄金/ETF/基金/可转债，驱动建仓问题、计划模板、复盘指标 |
| 主应用 UI 冗余，软件要方便人用 | 侧边栏从 8 项减到 4 项；AI 改成全局侧栏，通知改成铃铛抽屉；合并计划和流水 |
| 尽量自动化，减少人的操作 | 新增自动化设置：行情、框架推断、复盘创建、简报、档位匹配、草稿生成；写入仍需确认 |
| 表设计要清晰，后续导入历史交割单 | 新增账户、导入批次、成交事实、公司行为表；金额用整数分、价格/数量用定点整数；导入可预览、去重、回滚 |
| 应用要有记忆，形成自己的投资风格 | 新增记忆与风格：分层记忆、证据、置信度、复盘对话、风格快照；原则由用户确认 |

产品目标不是让 AI 荐股，而是把「选—买—持—卖—复盘」变成可执行、会提醒、能积累的纪律系统。盈利来自仓位、风险预算、执行和复盘；AI 负责降低摩擦、补齐反面证据、整理记忆。AI 不承诺收益，最终决策由人确认。

三个不可妥协的边界：

1. AI 不直接写持仓和计划，只能生成草稿；记忆中的原则和偏好也必须用户确认。
2. 关掉 AI 后，持仓、计划、成交、导入、复盘、通知、记忆查看全部可用。
3. 不接券商、不下单、不存券商凭证；行情仍只来自东方财富和新浪。

## 4. 应用外壳与交互

### 4.1 菜单栏

- 左键只读面板：名称、现价、涨跌、今日/总盈亏、持仓、成本、仓位、下一档、↗。
- 行点击进持仓详情；↗ 进总览；提醒点击进对应页面。
- 右键严格三项：打开 Carapace、版本号（禁用）、退出。
- 面板不提供编辑；行情异常行显示 `—`。

### 4.2 主窗口

- 1180×760，最小 980×640；关闭窗口不退出。
- 侧边栏 4 项：总览、持仓、复盘、设置。
- 标题栏：页面标题、⌘K 搜索、AI 侧栏按钮、通知铃铛、刷新、新建持仓。
- 持仓内部分段：持仓 / 计划 / 流水。
- 复盘内部分段：复盘 / 记忆 / 风格。
- 设置子页：AI 模型 / 分析框架 / 自动化 / 通知 / 行情与数据 / 关于。

### 4.3 全局 AI 侧栏

- 右侧 396，随时可开，不跳页；⌘J 切换。
- 上下文跟随当前页面：总览=组合，持仓详情=当前标的，复盘=当前复盘，记忆=当前记忆。
- 显示模型、引用记忆、工具活动、草稿卡；可展开为全屏对话。
- 所有修改仍是草稿；侧栏不会遮挡主操作（可关闭/收起）。

### 4.4 通知抽屉

- 铃铛打开右侧抽屉；2 条未读等计数在铃铛上。
- 筛选：全部 / 未读 / 价格 / 复盘 / AI 与草稿 / 记忆。
- 点击开详情 sheet；支持确认、稍后、查看持仓、通知设置。
- 不占侧边栏入口；系统通知点击带 `carapace://` 深链。

## 5. 数据模型

### 5.1 命名与类型约定

| 项 | 约定 |
|---|---|
| 表/列 | 小写下划线；表名复数 |
| 主键 | `id INTEGER PRIMARY KEY AUTOINCREMENT` |
| 外部标识 | `broker_trade_id`、`order_id`、`dedupe_key` 用 TEXT |
| 时间 | ISO8601 带时区，如 `2026-11-05T14:32:05+08:00`；交易日 `YYYY-MM-DD` |
| 金额 | 导入事实用整数分：`amount_minor`、`fee_*_minor` |
| 价格 | `price_scaled INTEGER` + `price_scale INTEGER`（默认 10000，即 4 位小数） |
| 数量 | `quantity_scaled INTEGER` + `quantity_scale INTEGER`（默认 10000） |
| 投影 | `positions.quantity` / `avg_cost` 仍用 REAL 供 UI；导入原始值保留在事实表 |
| 删除 | 导入事实不物理删除；`status='void'` + `voided_at`；投影可重建 |
| 去重 | `dedupe_key TEXT UNIQUE`；优先成交编号，否则规范化字段哈希 |

### 5.2 现有表（v3 基础）

`positions`、`plans`、`changes`、`alerts`、`meta` 保留，语义不变：

- `changes` 是持仓业务事件流水：建仓、买卖、清仓、修正、成本、计划版本。
- `positions` 是当前投影，可由 `changes` 重建。
- `plans` 每持仓唯一，档位有稳定 `id`。
- 所有写操作单事务，先写 `changes` 再更新投影。

### 5.3 账户与交割单

```sql
CREATE TABLE accounts (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  broker        TEXT NOT NULL,              -- 华泰 / 东方财富 / 中信…
  name          TEXT NOT NULL,              -- 显示名
  account_no    TEXT,                       -- 脱敏后的账号
  currency      TEXT NOT NULL DEFAULT 'CNY',
  timezone      TEXT NOT NULL DEFAULT 'Asia/Shanghai',
  is_default    INTEGER NOT NULL DEFAULT 0,
  created_at    TEXT NOT NULL
);

CREATE TABLE import_mappings (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  broker        TEXT NOT NULL,
  name          TEXT NOT NULL,
  version       INTEGER NOT NULL DEFAULT 1,
  mapping_json  TEXT NOT NULL,              -- 券商列 -> 标准字段
  created_at    TEXT NOT NULL,
  updated_at    TEXT NOT NULL
);

CREATE TABLE import_batches (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id    INTEGER NOT NULL REFERENCES accounts(id),
  broker        TEXT NOT NULL,
  file_name     TEXT NOT NULL,
  file_hash     TEXT NOT NULL,
  mapping_id    INTEGER REFERENCES import_mappings(id),
  status        TEXT NOT NULL,              -- preview | committed | voided | failed
  rows_total    INTEGER NOT NULL DEFAULT 0,
  rows_imported INTEGER NOT NULL DEFAULT 0,
  rows_skipped  INTEGER NOT NULL DEFAULT 0,
  rows_error    INTEGER NOT NULL DEFAULT 0,
  error         TEXT,
  started_at    TEXT NOT NULL,
  finished_at   TEXT
);

-- 成交事实：一笔券商成交一行，不可变；导入后只允许整批作废
CREATE TABLE executions (
  id                   INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id           INTEGER NOT NULL REFERENCES accounts(id),
  batch_id             INTEGER REFERENCES import_batches(id),
  broker_trade_id      TEXT,
  order_id            TEXT,
  code                 TEXT NOT NULL,
  name                 TEXT,
  side                 TEXT NOT NULL CHECK (side IN ('buy','sell')),
  quantity_scaled      INTEGER NOT NULL,
  quantity_scale       INTEGER NOT NULL DEFAULT 10000,
  price_scaled         INTEGER NOT NULL,
  price_scale          INTEGER NOT NULL DEFAULT 10000,
  amount_minor         INTEGER NOT NULL,
  fee_commission_minor INTEGER NOT NULL DEFAULT 0,
  fee_stamp_minor      INTEGER NOT NULL DEFAULT 0,
  fee_transfer_minor   INTEGER NOT NULL DEFAULT 0,
  fee_other_minor      INTEGER NOT NULL DEFAULT 0,
  fee_total_minor      INTEGER NOT NULL DEFAULT 0,
  currency             TEXT NOT NULL DEFAULT 'CNY',
  trade_time           TEXT NOT NULL,
  settle_date          TEXT,
  source               TEXT NOT NULL DEFAULT 'import', -- manual | import | api
  raw_json             TEXT,
  dedupe_key           TEXT NOT NULL,
  change_id            INTEGER REFERENCES changes(id),
  status               TEXT NOT NULL DEFAULT 'active',  -- active | void
  voided_at            TEXT,
  created_at           TEXT NOT NULL,
  UNIQUE (dedupe_key)
);
CREATE INDEX idx_executions_code_time ON executions(code, trade_time);
CREATE INDEX idx_executions_batch ON executions(batch_id);

-- 公司行为：分红、送转、配股、份额折算等
CREATE TABLE corporate_actions (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  account_id     INTEGER NOT NULL REFERENCES accounts(id),
  batch_id       INTEGER REFERENCES import_batches(id),
  code           TEXT NOT NULL,
  action_type    TEXT NOT NULL,             -- dividend | split | rights | transfer
  ex_date        TEXT NOT NULL,
  pay_date       TEXT,
  quantity_scaled INTEGER,
  quantity_scale  INTEGER DEFAULT 10000,
  amount_minor   INTEGER,
  note           TEXT,
  status         TEXT NOT NULL DEFAULT 'active',
  created_at     TEXT NOT NULL
);
```

`positions` 增加：`account_id`、`profile_id`、`profile_snapshot`（建仓时的框架快照）。`changes` 增加：`execution_id`、`batch_id`、`account_id`、`source`、`voided_at`。

## 6. 交割单导入

### 6.1 支持范围

- 第一阶段：CSV（UTF-8/GBK）、券商导出的 Excel 另存 CSV。
- 账户：多账户；默认账户用于手工记账。
- 字段：成交日期、证券代码/名称、方向、数量、价格、金额、佣金、印花税、过户费、其他费用、成交编号、订单编号、币种、备注。
- 公司行为：分红、送转、配股、份额折算作为独立事实导入。

### 6.2 流程

```text
选择文件 → 识别账户/券商 → 字段映射（可保存） → 规范化
→ 校验/去重 → 预览（可导入/重复/待确认/错误）
→ 确认导入（事务） → 写批次 + executions + changes
→ 重建受影响持仓 → 对账 → 结果页（可回滚整批）
```

### 6.3 校验与去重

| 检查 | 处理 |
|---|---|
| 必填字段缺失 | 错误行，不导入 |
| 日期/方向/数量/价格非法 | 错误行 |
| 金额与数量×价格差异 > 0.01 | 待确认，显示差额 |
| 费用缺失 | 待确认，允许按 0 导入 |
| 卖出数量超过当时持仓 | 待确认，导入后持仓为负则阻止提交 |
| 重复行 | `dedupe_key` 命中则跳过 |
| 未知代码 | 待确认，允许先导入再补名称 |
| 币种非 CNY | 待确认，当前只支持 CNY 估值 |

### 6.4 对账与回滚

- 对账：文件总行数/买入金额/卖出金额/费用 vs 数据库汇总；差异逐项列出。
- 回滚：整批 `status='voided'`，关联 `changes` 标记 void，重建持仓；不物理删除。
- 同一文件重复导入：`file_hash` 命中提示「已导入过」，可查看批次。
- 手工修正：导入后仍可用「编辑持仓」修正，但会新增 change，不覆盖原始 execution。

### 6.5 UI

- 入口：持仓·流水页「导入交割单」、设置·行情与数据、命令面板。
- Sheet 宽 760，四步：选择文件 → 字段映射 → 预览校验 → 完成。
- 预览表显示状态；底部「将导入 / 重复跳过 / 待确认」计数。
- 结果页显示批次、对账、回滚按钮。
- 自动化：监视文件夹，新文件先预览，不自动提交有错误的批次。

## 7. AI Agent

### 7.1 网关与协议

| 协议 | 端点 | 用途 |
|---|---|---|
| magpie（本机网关） | `127.0.0.1:3425`，`/api/hello`、`/v1/models`、`/v1/chat/completions` | 首选；一个供应商拿到所有模型 |
| OpenAI Chat Completions | `/v1/chat/completions` | 直连 OpenAI 或兼容服务 |
| OpenAI Responses | `/v1/responses` | 新版 OpenAI / magpie |
| Anthropic Messages | `/v1/messages` | Claude 直连；`x-api-key`、`anthropic-version` |
| Gemini generateContent | `/v1beta/models/{model}:generateContent` | Google 直连 |
| Ollama | `127.0.0.1:11434/v1`（OpenAI 兼容） | 本地模型 |

- magpie 端口读 `~/.config/magpie/settings.json` 的 `port`，默认 3425。
- 认证：magpie 用 `Authorization: Bearer magpie-app-id` 或 `x-api-key`；其他供应商各自协议。
- `User-Agent: Carapace/0.5 (darwin)`；`X-Magpie-Session` 可选。
- 模型目录永远从 `/v1/models` 读取，不内置清单；支持 `?kind=image,video` 扩展。

### 7.2 模型目录

- 展示全部模型，按供应商分组；搜索、能力筛选、收藏。
- 每行：显示名、模型 id、供应商、能力（工具/推理/图片/长上下文/本地）、上下文、最大输出、推理档位、收藏。
- 模型详情：协议、端点、能力、测试工具调用、设为对话/建仓模型。
- 能力未知时标记「未知」，首次调用后记录；无工具模型自动降级 JSON 模式。
- 收藏模型进入任务路由快捷列表。

### 7.3 任务路由

| 任务 | 默认模型 | 推理 | 回退 |
|---|---|---|---|
| 对话 | claude-sonnet-4.5 | medium | claude-haiku-4.5 |
| 建仓 | claude-opus-4.5 | high | claude-sonnet-4.5 |
| 计划复核 | claude-opus-4.5 | medium | gpt-5.1 |
| 复盘 | claude-opus-4.5 | high | claude-sonnet-4.5 |
| 简报 | claude-haiku-4.5 | low | claude-sonnet-4.5 |
| 提醒解释 | claude-haiku-4.5 | low | claude-sonnet-4.5 |
| 风险检查 | gpt-5.1 | medium | claude-sonnet-4.5 |

- 每个任务可选任意目录模型和推理档位；支持回退模型。
- 分析框架覆盖提示词和指标，不覆盖模型路由。
- 调用失败/超时/无工具时自动回退；连续失败提示切换模型。

### 7.4 接入示例

设置·AI 模型·接入示例提供 5 个页签：magpie、OpenAI、Anthropic、Gemini、Ollama。每个页签给 curl 和 SDK 片段、Base URL、认证头和模型 id 的取法，支持复制。

### 7.5 Agent 循环与工具

```text
输入/技能触发 → ContextBuilder（持仓、计划、复盘、框架、记忆）
→ 任务路由选模型 → 流式消息 + 工具调用
→ 只读工具执行 → 草稿/记忆提议 → 最多 8 轮
→ 用户确认 → 写入
```

工具：

| 类型 | 工具 |
|---|---|
| 只读 | `portfolio_snapshot`、`position_detail`、`quote_lookup`、`risk_report`、`review_context`、`search_memory`、`list_profiles`、`list_models` |
| 草稿 | `propose_position_draft`、`propose_plan_draft`、`propose_trade_draft`、`propose_review_summary` |
| 记忆 | `propose_memory`（新增/更新/取代） |

禁止：任意 URL、文件读写、Shell、直接 SQL、直接写业务表。

### 7.6 上下文与记忆

- 默认：当前标的、当前计划、最近 20 条流水、最近 3 次复盘。
- 记忆检索：全局原则 + 当前框架 + 当前标的 + 当前持仓 + 最近教训，最多 20 条；按 scope、置信度、最近使用排序。
- 提示词要求引用记忆编号，区分事实/判断，不承诺收益。
- 请求审查可看完整上下文和引用的记忆。

### 7.7 失败与关闭

| 状态 | 行为 |
|---|---|
| 网关未运行 | AI 入口显示未连接；手动功能照常 |
| 模型不支持工具 | 降级无工具 JSON；提示可靠性 |
| 超时/限流 | 重试 1 次，回退模型 |
| 上下文过长 | 截断旧消息，保留事实和记忆摘要 |
| 用户关闭 AI | 不初始化网络；隐藏 AI 入口；记忆和手动流程保留 |

## 8. 分析框架

### 8.1 内置框架

| 框架 | 关注 | 计划模板 | 复盘重点 |
|---|---|---|---|
| A股个股 | 商业模式、增长、估值、催化、风险 | 分批买入 + 止损 + 目标 | 逻辑、估值、执行偏差 |
| 黄金 | 实际利率、美元、央行购金、地缘 | 区间 + 定投 + 止损 | 宏观逻辑、目标权重 |
| ETF/指数 | 估值分位、资金流、跟踪误差、成分股盈利 | 定投 + 网格 + 再平衡 | 估值、资金、跟踪 |
| 基金 | 经理、风格、回撤、同类排名 | 定投 + 再平衡 | 经理/风格变化 |
| 可转债 | 转股溢价、纯债溢价、正股、剩余年限 | 债底 + 溢价 + 强赎 | 溢价、强赎、正股 |
| 自定义 | 用户复制内置框架后修改 | 用户定义 | 用户定义 |

### 8.2 框架如何生效

| 环节 | 使用方式 |
|---|---|
| 建仓 | 推断框架（代码/来源）→ 问题清单 → AI 追问 1 个关键问题 |
| 仓位 | 框架风险规则 + 总资金/风险预算 → 建议数量 |
| 计划 | 模板生成档位；AI 解释理由；用户可手写/改 |
| 复盘 | 指标与问题由框架决定；缺失指标标「待补充」 |
| AI | 提示词包含框架、指标、计划模板和记忆 |
| 历史 | `plans.profile_snapshot` 保留当时框架，避免后续改框架影响旧复盘 |

### 8.3 自动与手动指标

- 自动：价格、昨收、涨跌、市值、盈亏、成交、持仓天数、计划执行、最大回撤（有采样时）。
- 手动：基本面、估值分位、宏观指标、基金经理、溢价率等，当前没有数据源；UI 明确标注，AI 只提问不编造。
- 未来：数据适配器统一写 `position_metrics(source='auto')`，不改框架定义。

### 8.4 计划可以手写

- 计划编辑器不依赖 AI；框架只提供默认模板和校验提示。
- 手写计划同样进入 diff、版本和复盘闭环。
- AI 生成失败时，编辑器仍可完成建仓。

## 9. 记忆、风格与体系

### 9.1 记忆分层

| 范围 | 例子 | 写入 |
|---|---|---|
| 全局 | 「不在盘中追高」「分批建仓」 | 用户确认 |
| 框架 | 「黄金只做配置」「个股偏好季报拐点」 | 用户确认 |
| 标的 | 「第二档不要挂太近」「季报扣非连续改善」 | 事实可自动，教训需确认 |
| 持仓 | 「这次情绪卖出」「本周期计划执行 4/5」 | 事实自动，判断确认 |

### 9.2 记忆字段

- 类型：原则、偏好、模式、教训、事实、待验证。
- 证据：复盘、成交、计划版本、指标；无证据不写入。
- 置信度：0–1；重复验证提升，矛盾降低。
- 状态：生效、待复核、已取代、归档。
- 取代：新记忆可标记旧记忆 `superseded_by`，不删除，保留历史。

### 9.3 复盘对话

1. AI 读取事实、框架、相关记忆，先问 2–3 个问题。
2. 用户用自己的话回答；AI 不急着总结。
3. AI 归纳「事实 / 判断 / 偏差 / 下一步」，生成复盘草稿。
4. AI 提议 0–3 条记忆（新增/更新/取代），用户勾选确认。
5. 用户完成复盘；下次复盘和简报引用这些记忆。

### 9.4 风格

- 指标：持有周期、集中度、计划执行率、计划外成交率、复盘完成率、加减仓模式、品种分布、盈利来源、最大回撤。
- 叙述：AI 草稿，用户可编辑；每次月度/季度复盘生成 `style_snapshots`。
- 体系：原则 + 偏好 + 教训 + 待验证，形成「我的体系 v1」；只由用户确认的内容构成原则。
- 风格变化：快照对比显示执行率、集中度、计划外交易的变化。

### 9.5 记忆边界

- 只在本机；可导出、清空、逐条删除。
- 不把一次结果当原则；待验证记忆不进入强提示。
- AI 引用记忆必须标编号；用户可点开证据。
- 记忆不是投资建议，不替代用户判断。

## 10. 核心流程

### 10.1 建仓

- 快速模式（默认）：代码 + 风险预算 → 框架推断 → AI 生成仓位与计划 → 一次确认。
- 完整模式：5 步（标的/逻辑/仓位/计划/确认），每步可改。
- 已有同代码持仓：默认加到现有持仓；新建周期需显式选择。
- 保存：持仓、计划、首条 change、建仓复盘待办、记忆事实（如需要）。
- 无 AI：空模板 + 框架提示，完全可手写。

### 10.2 计划

- 生成：按框架模板 + 风险预算 + 现价 + 记忆；输出档位、数量、条件、理由。
- 编辑：行内编辑、手写、AI 复核、自然语言修改。
- 保存：diff → 版本 +1 → 旧版本快照；冲突不覆盖。
- 自动化：档位触发时生成复核草稿；计划到期生成复盘。

### 10.3 成交

- 手动记一笔：数量/价格/费用/日期/档位；自动匹配最近未执行档位。
- 导入：交割单批量写入；自动关联档位（价格+方向+时间）。
- 计划外成交：标记并提示原因，进入复盘。
- 修正：编辑持仓并填原因；不覆盖事实。

### 10.4 清仓

- 预览净回款、已实现盈亏。
- 清仓后生成清仓复盘（结果、持有天数、最大浮盈/回撤、计划执行）。
- AI 可写复盘草稿，用户编辑；不自动改计划。

### 10.5 复盘

- 触发：计划到期、档位执行、清仓、周报/月报。
- 事实自动计算；框架指标缺失标「待补充」。
- 对话式复盘 + 结果归因 + 记忆提案 + 计划草稿。
- 完成后写入历史；下次复盘引用记忆。

### 10.6 简报

- 早盘 09:20：今日待办、隔夜变化、需确认草稿。
- 收盘 15:10：今日盈亏、贡献/拖累、触发、明日待办。
- 周五 15:30：本周结果、执行、记忆更新、下周计划。
- 有 AI 用任务路由生成；无 AI 用事实模板。

## 11. 通知

| 类型 | 触发 | 渠道 | 去重 |
|---|---|---|---|
| 价格穿越 | 穿越未执行档位 | 状态栏/系统/抽屉 | 每档每日 1 次 |
| 止损 | 触及止损/风控线 | 系统 critical | 每档每日 1 次 |
| 复盘到期 | 计划/定期复盘到期 | 系统/抽屉 | 每天 1 次 |
| 仓位/回撤 | 超单只上限/回撤阈值 | 状态栏/抽屉 | 每天 1 次 |
| 行情异常 | 连续失败/时间戳不更新 | 状态栏/抽屉 | 30 分钟 1 次 |
| 草稿待确认 | 新草稿 | 抽屉/状态栏 | 每草稿 1 次 |
| 记忆待确认 | 新记忆提案 | 抽屉 | 每提案 1 次 |
| 简报 | 早/收盘/周报 | 抽屉 | 每期 1 次 |
| AI 任务完成 | 后台任务 | 抽屉 | 每任务 1 次 |

- 免打扰 22:30–07:30 只保留止损。
- 合并同持仓同日提醒；确认只影响状态栏标记。
- 应用退出不发送；登录启动可选。
- 通知文案先结论、再数字、再动作；不写「必涨/必跌」。

## 12. 盈利导向

- 总览：今日/本周盈亏、贡献最大/拖累最大、计划执行、计划外、最大回撤、止损风险。
- 复盘：结果归因（已实现、未实现变化、贡献、回撤）、执行偏差、下一步。
- 风格：盈利来源、常见模式、执行率趋势。
- 风险：仓位上限、集中度、止损风险、回撤阈值。
- 明确不做：AI 选股、涨跌预测、收益承诺、自动下单。

## 18. 风险

| 风险 | 对策 |
|---|---|
| 模型工具调用不稳 | 任务路由 + 工具校验 + 一次重试 + JSON 降级 |
| 模型太多选择困难 | 收藏 + 任务路由 + 默认回退；目录可搜索 |
| 框架指标缺失 | 标注自动/手动；AI 提问不编造；手写不阻塞 |
| 导入脏数据 | 预览、去重、待确认、对账、整批回滚 |
| 记忆写错 | 证据 + 置信度 + 用户确认；可编辑/取代/归档 |
| 自动化越界 | 写入一律确认；原则/偏好不自动写 |
| 复盘负担 | 对话 2–3 问、AI 整理、允许跳过、周报可选 |
| 数据迁移损坏 | 备份、事务、单测、只增不删 |
